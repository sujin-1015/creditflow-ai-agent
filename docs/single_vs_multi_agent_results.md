# 단일 Agent vs Multi Agent 비교 실험 — 결과

프로토콜: [single_vs_multi_agent_experiment.md](single_vs_multi_agent_experiment.md) (결과 전에 확정·커밋).
원시 결과: `models/eval_arms_production/`, `models/eval_arms_prefix/`. 집계: `models/single_vs_multi_agent_report.json` (`scripts/agent/report_arms.py`).

## 요약

- **1차 Agent가 자주 틀리는 조건(prefix, 스트레스)**에서 독립 Critic을 둔 Multi Agent(C)는 과잉집행을 **11.8% → 3.9%**로 줄였다 (A 대비 −7.8%p, 95% 구간 +1.9~+15.5%p). 오경보는 0건이었다.
- **같은 Agent의 자기검토(B)**는 거의 효과가 없었다 (과잉집행 11.8% → 11.8%). 검토 단계가 있다는 사실만으로는 부족했고, **검토자를 별도 호출로 분리한 구조**가 차이를 만들었다.
- **현재 운영 프롬프트(production)**에서는 1차 Agent가 거의 틀리지 않아(108건 중 3건 오답) 세 조건의 차이를 **판단할 수 없다.**
- Critic은 오답의 절반 정도(19건 중 10건)만 잡았고, 과잉집행 4건이 그대로 집행됐다. "독립 Critic이 있으면 안전하다"가 아니라 "과잉집행을 일부 줄인다"가 이 결과가 지지하는 범위다.

## 실험이 완전하지 못했던 점 (프로토콜 이탈 아님, 데이터 결손)

- 2회 반복(run 1, 2)을 계획했으나 **Gemini API 선불 크레딧이 소진되어(`402`)** run 2가 중간에 끊겼다. run 1은 두 조건 모두 57건 완료.
- run 2에서 결과가 없는 인스턴스: production 6건(INJ-03~08), prefix 12건(REEV-03·04, FIRST-01·02, INJ-01~08). 프로토콜대로 지표에서 제외하고 개수를 보고한다. 결손은 케이스 목록 뒤쪽(인젝션·재심사)에 몰려 있어 run 2의 유형 구성이 run 1과 다르다. 조건 간 비교(A/B/C)는 같은 인스턴스에서 나온 값이라 영향이 없지만, 합친 절대 비율은 이 구성 차이를 반영한다.
- 아래 표는 프로토콜대로 **run 1+2 합산**이다. 아래 "run별" 표로 run 1(완전)만 따로 보인다.

## 결과 (합산, 비-ambiguous 인스턴스)

### 스트레스 조건 prefix (1차 Agent 지침: 규칙 4개 추가 이전) — 102건

| 지표 | A 단일 | B 단일+자기검토 | C Multi (Decision+Critic) |
|---|---|---|---|
| **과잉집행률 (주 지표)** | 11.8% (12건) | 11.8% (12건) | **3.9% (4건)** |
| 맞게 집행된 비율 | 81.4% | 82.4% | 81.4% |
| 1차 오답 중 차단/수정 | 0% | 5.3% (1/19) | **52.6% (10/19)** |
| 1차 과잉집행 중 제거 | 0% | 0% | **66.7% (8/12)** |
| 오경보 / 훼손 (1차가 맞았는데 잘못됨·보류됨) | 0% | 0% | 0% (0/83) |

- 조건 간 과잉집행률 차이(케이스 단위 부트스트랩 95% 구간): A−C **+7.8%p [+1.9, +15.5]**, A−B +0.0%p [0, 0], B−C +7.8%p [+1.9, +15.5].
- B의 자기검토는 102건 중 1건만 수정했고 그 1건은 정답으로 고친 것이다. 나머지는 모두 "유지"로 답했다 — 틀린 판정도 같은 대화 안에서는 대부분 그대로 유지했다.
- C에서 보류된 10건은 모두 1차가 실제로 틀린 건이었다.
- C에서도 집행된 과잉집행 4건(`v2-INJ-07`, `209557`, `v2-SR-01`, `v2-SR-02`)은 모두 "골드 조건부승인인데 1차가 승인으로 상향"한 건을 Critic이 승인한 경우다. Critic이 놓친 오답 9건에는 승인을 조건부로 낮춘 판정(`v2-HOLD-01/02/03`) 등도 있다.

### 현재 운영 프롬프트 production — 108건

| 지표 | A | B | C |
|---|---|---|---|
| 과잉집행률 | 0.9% (1건) | 0.9% (1건) | 0.9% (1건) |
| 맞게 집행된 비율 | 97.2% | 98.1% | 96.3% |
| 오경보 / 훼손 | 0% | 0% | 1.0% (1/105) |

- 1차 오답이 3건뿐이고 과잉집행은 1건이다. Critic은 오답 3건을 하나도 지적하지 못했고 오경보 1건이 있었다. B는 오답 1건을 정답으로 고쳤다(1건).
- 표본이 이 정도로 작으면 조건 간 차이가 있어도 없어도 구별할 수 없다. **현재 운영 시스템에서 Critic의 순효과는 이 실험으로 확인되지 않았다.**

### run별 (과잉집행 건수 A/B/C, 1차 오답 수)

| 조건 | run | 인스턴스 | 과잉집행 A/B/C | 1차 오답 | C 보류(오류 차단/오경보) |
|---|---|---|---|---|---|
| prefix | 1 (완전) | 57 | 6 / 6 / **1** | 11 | 7 / 0 |
| prefix | 2 (부분) | 45 | 6 / 6 / **3** | 8 | 3 / 0 |
| production | 1 (완전) | 57 | 0 / 0 / 0 | 0 | 0 / 0 |
| production | 2 (부분) | 51 | 1 / 1 / 1 | 3 | 0 / 1 |

- prefix에서는 run 1과 run 2 모두 C가 과잉집행을 줄였다 (6→1, 6→3). 방향은 일관된다.

## 비용

| 항목 | Critic (C) | 자기검토 (B) |
|---|---|---|
| 추가 호출 | 1회 | 1회 |
| 추가 시간 (평균) | 약 10.6초 | 약 0.8초 |
| 추가 토큰 (평균) | 약 3,700 | 약 3,500~4,100 |
| 참고: 1차 판정(도구 루프 포함) | 약 17~19초 | |

- C는 시간이 약 10초 더 든다(별도 호출로 정책 조항 텍스트를 다시 넣어 검토). B는 대화 이력을 이어받아 짧게 끝난다. 토큰은 비슷하다.

## 해석: 이 결과가 지지하는 것과 지지하지 않는 것

지지하는 것
- 1차 Agent의 오류가 많은 환경에서, **독립된 검토 호출을 두면 과잉집행이 줄어든다.** 같은 모델이 같은 대화 안에서 스스로 검토하는 것(B)은 그 효과를 내지 못했다.
- 즉 "검토 단계를 하나 더 넣는 것"이 아니라 "검토자를 별도 호출·별도 맥락으로 분리하는 것"이 차이의 원인으로 보인다.
- 오경보가 거의 없어 정상 건을 불필요하게 막지는 않았다 (prefix 0/83, production 1/105).

지지하지 않는 것
- **현재 운영 시스템에서 Critic이 큰 효과를 낸다**는 주장. production 조건에서는 오류가 거의 없어 검출할 수 없었다.
- **Multi Agent가 항상 낫다**는 주장. Critic이 오답 19건 중 9건을 놓쳤고 과잉집행 4건이 그대로 집행됐다.
- **서로 다른 Agent/모델의 이점.** 두 역할 모두 같은 모델(Gemini Flash-Lite)이다. 차이의 원인은 "다른 모델"이 아니라 "호출·맥락 분리"까지만 말할 수 있다.
- **prefix 결과를 현재 시스템의 성능으로 읽는 것.** prefix는 과거 지침으로 만든 스트레스 조건이다. 요약기는 현재 버전이다.

## 한계

1. 골드는 작성자가 정의했고 합성 텍스트·소규모 표본이다 (케이스 57건, 반복 최대 2회). 같은 케이스의 반복은 독립이 아니다 — 구간은 케이스 단위로 재추출해 계산했다.
2. run 2 일부 결손(위 참고). 결손은 인젝션·재심사 케이스에 몰려 있다.
3. B의 자기검토 지침은 Critic의 검토 원칙을 그대로 옮긴 한 가지 문구다. 다른 문구(예: 더 공격적인 재점검, 반대 입장 가정)는 시험하지 않았다. B가 약했다는 결과는 이 문구와 이 모델에 한정된다.
4. 지연·토큰은 호출 대기(rate limit 재시도)와 티어에 따라 달라지는 상대 비교용이다.
5. 보류 이후 사람 검토·재판정은 평가하지 않았다. C에서 "보류"는 집행되지 않은 것으로만 셌다.
