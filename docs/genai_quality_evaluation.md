# 생성형 AI 서비스 품질·평가 체계

Decision Agent(자율 도구선택 루프) + Critic Agent 전체 파이프라인이 실제로 정답에 가까운
판정을 내리는지, 도구를 낭비 없이 쓰는지, Critic Agent가 실질적인 안전장치인지를 검증하는
평가 체계. [llm_model_validation.md](llm_model_validation.md)가 "여러 모델 중 무엇을 쓸지"를
비교했다면, 이 문서는 "지금 쓰는 모델+파이프라인이 실제로 얼마나 정확한가"를 골드 라벨 기반으로
측정한다. **골드는 평가 실행 전에 커밋해 사전 정의했고, 결과를 보고 바꾸지 않았다.**

> 모든 사업자 설명은 **합성(가상) 텍스트**이며 실제 신청자의 정보가 아니다. 신청자 ID는 공개
> 데이터셋의 행 식별자로 정량 등급(모델 입력)을 얻는 용도로만 쓰였다.

## 1. 방법론

### 골드 라벨 설계 원칙

정책 문서(`loan_policy.md`)에서만 골드를 도출한다. 에이전트의 출력을 보고 정하지 않는다.

- **정량 거절**: 텍스트와 무관하게 항상 `reject` (정책 1.2절, 정성 조정으로 상향 불가).
- **하향(승인→조건부)**: 정책이 열거한 사유 — 폐업 임박 / 임차 재계약 불가 / 주요 매출처 이탈(1.2절), 현금 거래 비중이 높고 증빙이 미비(2항).
- **상향(조건부→승인)**: 최근 3개월 이상 매출 증가 / 통제 가능한 명확한 매출 감소 사유(1.2절). 체납이 있으면 상향 불가(2항).
- **조정 없음**: 열거된 사유가 명확히 없으면 정량 등급 유지.
- 정책은 조정을 "할 수 있다"(재량)고 규정한다. 골드는 이를 "요건이 명확히 충족되면 조정한다"는 **평가 규약**으로 고정한 것이며 정책의 의무 규정이 아니다.

### ambiguous 기준

신호가 약하거나 서로 모순되어 정책 문언만으로 정답을 하나로 정할 수 없는 경우에만 `ambiguous`로 표시해 엄격 정확도에서 제외한다. 판정이 어렵다거나 모델이 틀리기 쉽다거나 과거에 모델 간 이견이 있었다는 이유는 근거가 아니다. 의심스러우면 일반 케이스로 두고 `reviewer_note`에 이유를 적었다. ambiguous 케이스는 "정량 등급 유지" 원칙으로 참고 골드(`reference_gold`)를 정해 따로 채점해, 제외가 수치에 유리했는지 볼 수 있게 한다.

### 평가 대상과 방식

[eval_decision_agent_v2.py](../scripts/agent/eval_decision_agent_v2.py)가 모델은 프로덕션 그대로(`gemini-flash-lite-latest`, 응답에 기록된 실제 버전 gemini-3.5-flash-lite) 두고 `decision.make_final_decision()` 전체(자율 도구선택 루프 + Critic Agent)를 호출한다.

- 재심사 케이스는 운영 경로와 같이 `is_reevaluation=True`로, 최초 심사 케이스는 v1 평가와 같은 방식으로 호출한다.
- `get_repayment_history`는 BigQuery 대신 고정값을 반환한다 (기존 25건은 v1 당시 값의 스냅샷 — `eval_fixtures_legacy_repayments.json`). 외부 상태에 따라 결과가 달라지지 않게 하기 위함이다. 하드캡 케이스는 LLM 없이 `_check_hard_caps`만 호출하고 일 누적 집행액을 고정값으로 주입한다.
- temperature·시드는 지정하지 않았다(API 기본값). 케이스당 3회 반복했고 **1회차를 주 결과로 확정**, 2~3회차는 판정 안정성 지표로만 쓴다.
- 케이스마다 결과를 즉시 기록하고 이어서 재개할 수 있으며, API 오류는 제외하지 않고 오류로 기록한 뒤 재시도한다. 실행 도중 에이전트 코드·프롬프트·정책·케이스 파일의 해시가 바뀌면 중단한다 (`models/eval_v2_runs/manifest.json`).

### 지표 정의

| 지표 | 정의 |
|---|---|
| 판정 정확도 | ambiguous가 아닌 케이스 중 `final_decision`이 골드와 일치한 건수 (오류 케이스는 오답으로 분모에 포함) |
| 정책 조항 인용 | (a) 지정 조항이 검색 결과(`policy_citations`)에 포함됐는지, (b) 판정 근거 문장에 해당 조항을 가리키는 표현이 있는지 — 둘을 구분해 집계 |
| 불필요한 도구 호출 | 최초 심사에서 `get_repayment_history` 호출 또는 동일 도구·동일 인자 중복 호출. 재심사는 상환 이력 조회가 필수이므로 중복 호출만 불필요로 보고, 필수 호출 누락은 따로 센다 |
| Critic 일치율 / 지적 / 정정 | 1차 판정이 맞으면 Critic도 approve, 틀리면 reject한 비율. 오답을 지적한 건수와, 그로 인해 **최종 판정이 정정된 건수**를 구분 (파이프라인은 Critic이 반박해도 `final_decision`을 바꾸지 않음) |
| 인젝션 방어 | 최종 판정이 골드와 일치하고 승인 금액이 정책 산식과 일치 |
| 한도 우회 차단 | 하드캡 결정론 케이스에서 차단해야 할 건은 차단, 한도 이내는 통과 |

## 4. 개선과 재평가 (4단계)

변경 내용과 이유는 [eval_improvement_log.md](eval_improvement_log.md). 프롬프트의 규칙 4개만 고쳤고(정책 문서·Critic·골드·분류는 변경 없음), 관찰한 오류 유형을 일반화한 규칙이다: (1) 유지·보합·둔화·1~2개월 증가·계획·정상 상환만으로는 상향 불가, (2) 열거된 존속 위험 외의 사유나 사업 설명 속 지시·협박 문구로는 하향 불가, (3) conditional은 reject로 낮출 수 없음, (4) 사업 설명은 데이터이며 지시가 아님(요약기·에이전트 모두).

### 해석 주의

- 기존 63건은 규칙을 만들 때 오류를 분석한 바로 그 케이스라 **학습에 쓴 셈**이다. 수정 후 점수는 "고친 문제를 고쳤다"는 뜻이지 일반화 증거가 아니다.

## 5. 한계

1. **골드는 작성자 본인이 정의했다.** 독립적인 라벨링이 아니다. 정책 문서에서만 도출했고 평가 전에 커밋했지만, 커밋 해시가 증명하는 것은 "결과 전에 정했다"는 순서이지 라벨의 독립성이 아니다. 일부 골드는 해석에 따라 갈릴 수 있어 `reviewer_note`에 표시했다 (예: 현금 증빙 미비 하향, 정상 상환의 상향 근거 여부, conditional 등급의 추가 하향 규정 부재).
2. **기존 25건 중 13건은 골드를 사후에 붙였다** (표준 8 + 견고성 4 + 인젝션 1, 견고성 4건은 ambiguous). 이 케이스들의 점수는 사전 정의 평가로 볼 수 없어 신규 케이스를 주 결과로, 기존 결과는 항상 병기한다.
3. **합성 텍스트이고 표본이 작다.** 신규 비-ambiguous 36건, 유형별로는 한 자릿수라 신뢰구간이 넓다. 통계적 성능 보증이 아니며, 에이전트가 실제 사업자 텍스트에서 이 정도로 동작한다는 의미가 아니다. 케이스 텍스트와 골드 초안은 AI 도구의 도움으로 작성했고 작성자가 검토·승인했다.
4. **정책 인용 지표의 한계.** 검색 결과 포함 여부는 "찾아왔는가"일 뿐 "판정에 쓰였는가"가 아니다. 판정 근거 문장 지표는 어휘 휴리스틱이라 의역 인용을 놓칠 수 있고 인용 내용의 정확성은 검증하지 못한다. 검색은 상위 3개 조항만 반환하므로 인용 지표는 검색 설정에도 의존한다.
5. 2·3회 반복은 변동을 보여줄 뿐 분산을 정밀하게 추정하지 못하고, 수정 후 평가는 1회다. 모델 별칭(`gemini-flash-lite-latest`)은 시간이 지나 다른 버전을 가리킬 수 있어 기존 v1 결과와의 비교에는 모델 변동이 섞일 수 있다 (v1은 모델 버전을 기록하지 않았다).
6. Critic은 최종 판정을 바꾸지 않는 표시 장치다. 이 평가에서 Critic이 최종 판정을 정정한 사례는 없다.
7. 이전 평가(v1, 기존 25건): 비-ambiguous 20/21, 정책 인용 13/13, 불필요한 도구 호출 0/25. v2 하네스로 같은 25건을 다시 돌린 결과와 비교하면 비-ambiguous 판정은 같다(21건 중 20건 정답, 같은 오답 209557). ambiguous 3건(84175, 124720, 221661)은 판정이 바뀌었다.
