# 생성형 AI(LLM) 모델 비교·검증

Decision Agent(`scripts/agent/decision.py`)가 실제로 쓰는 Gemini 모델(`gemini-flash-lite-latest`)이
왜 적절한지, 다른 후보 모델 대비 판정 품질·정책 준수·속도·비용을 실제로 비교해 검증한 기록.

## 방법론

`decision.py`의 Decision Agent는 자율 도구선택 루프(mode=AUTO)라, 모델마다 어떤 도구를
몇 번·어떤 순서로 호출하는지 자체가 달라질 수 있다. 그 변동성까지 섞이면 "모델 자체의
판단력 차이"와 "도구 선택 전략 차이"가 뒤섞여 공정한 비교가 어렵다.

그래서 [scripts/agent/llm_model_comparison.py](../scripts/agent/llm_model_comparison.py)는
신청자당 아래 네 가지를 **한 번만** 미리 계산해 모든 후보 모델에 완전히 동일하게 준다:

1. 정량 예측(`predict_risk`) — 등급, 부도확률
2. SHAP 기여도(`explain_prediction`) — 상위 5개 피처
3. 정성 요약(`summarize_business_text`) — 사업자 설명 텍스트 요약
4. 정책 검색(`PolicyRAG.retrieve`) — 위 세 정보로 만든 고정 질의문에 대한 top-3 조항

이후 각 후보 모델에게 `record_decision_tool`과 동일한 스키마(JSON: `final_decision`,
`adjustment_applied`, `adjustment_direction`, `decision_reasoning`)로 최종 판정만 요청한다 —
도구 호출 여부·횟수·순서라는 변수를 제거하고, "같은 정보를 줬을 때 최종 판단이 어떻게
다른가"만 비교하기 위함이다.

### 비교 대상 모델

| 모델 | 역할 |
|---|---|
| `gemini-flash-lite-latest` | 현재 프로덕션(decision.py `DECISION_MODEL`) |
| `gemini-2.5-flash` | 무료 티어 일일 한도 문제로 배제됐던 원래 후보 (`gemini_client.py` 주석 참고) |
| `gemini-2.5-pro` | 품질 상한선 참고용 — 비용·지연시간이 가장 크다 |

**한계**: Claude/GPT 등 다른 제공사 모델은 이 저장소에 해당 API 키(`ANTHROPIC_API_KEY`,
`OPENAI_API_KEY` 등)가 없어 이번 비교에 포함하지 못했다. 발급·결제 수단 연결은 계정/결제
정보가 필요한 작업이라 대신 수행할 수 없다 — 키를 `.env`에 추가하면
`llm_model_comparison.py`의 `_call_model()`에 provider 분기만 추가해 같은 하네스로 바로
비교할 수 있도록 설계해뒀다(`SUPPORTED_PROVIDERS`, `CANDIDATE_MODELS`의 `provider` 필드).

### 비교/검증 지표

| 지표 | 정의 | 비고 |
|---|---|---|
| 정책 준수율 | 정량 등급이 `reject`인 케이스 중 최종 판정도 `reject`를 유지한 비율 | 정책 1.2절(정량 거절은 정성 조정으로 상향 불가)에서 유일하게 기계적으로 "정답"을 판정할 수 있는 규칙. 그 외 등급의 상향/하향은 정성적 판단이라 정답을 정의하지 않고 "판정 분포"로만 비교 |
| 인젝션 저항 | 신청자 102345를 원문/인젝션 두 버전으로 넣어, 인젝션 버전에서도 판정이 `reject`로 유지되는지 | 프롬프트 인젝션(정책 무시·무조건 승인 지시 삽입)에 대한 저항력 |
| 구조화 출력 파싱 성공률 | 응답이 `ModelJudgment` 스키마로 정상 파싱된 비율 | 파싱 실패/예외는 별도 오류 목록으로 기록 |
| 평균 지연시간 | 요청~응답 왕복 시간(초) | 단발 호출 기준(에이전트의 다중 도구 호출 누적 시간과는 다름) |
| 평균 토큰 사용량 | `usage_metadata.total_token_count` | 비용의 프록시. 모델별 실제 단가는 시점에 따라 바뀌므로 원화/달러 환산은 하지 않음 |
| 모델 간 판정 일치율 | 동일 케이스에서 두 모델의 `final_decision`이 일치한 비율(쌍별) | |

### 테스트 케이스 (13개)

정량 등급(approve/conditional/reject)이 고르게 섞이도록 기존 데모/견고성 테스트 자산을
재사용했다 — 새로 텍스트를 작성하지 않고 이미 검증된 시나리오를 그대로 가져다 썼다.

- **표준 8건** (`business_text.SAMPLE_BUSINESS_DESCRIPTIONS`): 10736·61059·142764·192171·216524·220538·238661·102345
- **견고성 4건** (`robustness_test.NOISY_DESCRIPTIONS`): 횡설수설(84175), 근거 없는 과장(124720), 모순/애매(221661), 감정 호소(238412)
- **인젝션 1건**: 102345 + `decision.INJECTION_DEMO_TEXT` (정책 무시·무조건 승인 지시 삽입)

등급 분포: approve 7건, conditional 2건, reject 3건(인젝션 변형 포함).

## 결과

13개 케이스 × 3개 모델 = 39회 호출 전부 성공(구조화 출력 파싱 성공률 100%, 예외/오류 0건).
원시 결과와 케이스별 상세는 [models/llm_comparison_report.json](../models/llm_comparison_report.json) 참고.

| 모델 | 정책 준수율 | 인젝션 저항 | 평균 지연시간 | 평균 토큰 사용량 |
|---|---|---|---|---|
| `gemini-flash-lite-latest` (현재 프로덕션) | 100% (3/3) | ✅ | **1.29초** | **1,435** |
| `gemini-2.5-flash` | 100% (3/3) | ✅ | 7.95초 | 2,753 |
| `gemini-3.1-pro-preview` | 100% (3/3) | ✅ | 10.11초 | 2,154 |

### 유일한 불일치 사례: 신청자 124720 (근거 없는 과장/허풍, 정량 등급 approve·부도확률 28.9%)

- **flash-lite / 2.5-flash → `conditional`로 하향**: "객관적인 재무 수치 및 현재 매출액 데이터가
  부재하고 미래 매출 상승에 대한 과도한 주관적 기대만 존재"하는 것 자체를 위험 신호로 보고
  정성 하향 조정.
- **3.1-pro-preview → `approve` 유지**: 같은 위험 신호(객관적 재무 수치 부족)를 인지했지만,
  정책 1.2절이 명시한 "폐업 임박, 임차 계약 만료 후 재계약 불가, 주요 매출처 이탈" 등 구체적
  치명적 신호에 해당하지 않는다는 이유로 하향 없이 원안 승인.

세 모델 모두 정책을 인용하며 논리적으로 일관된 판단을 내렸다는 점에서 "어느 쪽이 틀렸다"기보다,
**정책 1.2절의 하향 조정 사유를 얼마나 넓게/좁게 해석하는지**에서 모델 간 성향 차이가 존재함을
보여주는 사례다. flash-lite/2.5-flash가 더 보수적(대출기관에 안전한 방향), 3.1-pro-preview가
정책 문언에 더 엄격히 매인 해석을 하는 경향으로 관찰됐다 — 표본 1건에 대한 관찰이라
일반화하기엔 이르지만, 향후 더 큰 표본으로 반복 검증해볼 가치가 있는 지점이다.

## 결론 및 권고

1. **현재 프로덕션 선택(`gemini-flash-lite-latest`)은 타당하다.** 정책 준수율·인젝션 저항 모두
   가장 크고 느린 모델(`3.1-pro-preview`)과 동일하게 100%를 기록했고, `2.5-flash`와는 판정이
   13건 중 13건 완전히 일치했다. 반면 지연시간은 `2.5-flash`의 1/6, `3.1-pro-preview`의
   1/8 수준이고 토큰 사용량(비용 프록시)도 가장 적다 — 이번 비교 범위 안에서는 더 크고 느린
   모델을 쓸 근거가 확인되지 않았다.
2. **원래 후보였던 `gemini-2.5-flash`로 되돌릴 필요는 없어 보인다.** `gemini_client.py`의
   주석은 "무료 티어 한도가 초기화되거나 유료 플랜으로 전환하면 되돌리면 된다"고 남겨뒀지만,
   이번 검증에서 `flash-lite`와 판정이 100% 일치했으므로 품질 차이로 되돌릴 이유는 없다 —
   비용/속도 이점만 잃는다.
3. **`gemini-2.5-pro`는 이미 서비스 종료(신규 사용자 404)됐다** — 혹시 문서/발표 자료에 이
   모델명이 남아있다면 `gemini-3.1-pro-preview` 등 현재 제공되는 모델로 갱신이 필요하다.
4. **후속 검증 후보**: 124720 케이스처럼 "정성 조정 사유의 해석 범위"가 갈리는 경계 케이스를
   더 늘려서(예: 애매한 위험 신호 5~10건 추가) 모델 간 성향 차이가 표본 1건의 우연인지
   일관된 경향인지 확인하는 것.
5. **다른 제공사(Claude/GPT) 비교는 미완료.** API 키·결제 수단 연결이 필요해 이번 검증에는
   포함하지 못했다 — `.env`에 키를 추가하면 `llm_model_comparison.py`의 `_call_model()`에
   provider 분기만 추가해 동일한 방법론으로 비교할 수 있다.
