# Decision Agent 평가셋 v2 — 설계 및 사전 정의 문서

> **상태: 평가 실행 전 / 사용자 검토 대기.** 이 문서와 `scripts/agent/eval_cases_v2.json`의 골드·분류는 평가 실행 전에 확정·커밋되어 '사전 정의'의 증거가 된다. 에이전트·평가 스크립트는 실행하지 않았다.

## 0. 합성 데이터 고지

모든 business_description은 합성(가상) 텍스트이며 실제 신청자의 정보가 아니다. applicant_id는 공개 학습 데이터셋의 행 식별자로서 정량 등급(모델 입력)을 얻기 위해서만 쓰였고, 텍스트의 내용과는 무관하다. v2-HC 케이스의 synthetic_applicant_id(99990x)는 데이터셋에 존재하지 않는 가상 ID다.

## 1. ambiguous 분류 기준

ambiguous는 사업자 설명의 신호가 약하거나 서로 모순되어, 정책 문서(조항 문언)만으로 정답을 하나로 정할 수 없는 경우에만 붙인다. 판정이 어렵거나 모델이 틀리기 쉽다는 이유, 과거에 모델 간 이견이 있었다는 이유는 ambiguous의 근거가 아니다. 의심스러운 경우는 ambiguous가 아니라 일반 케이스로 두고 reviewer_note에 이유를 적는다.

## 2. 골드 원칙

골드는 (1) 정량 등급이 reject이면 항상 reject, (2) 정책 1.2/2항이 열거한 사유가 없으면 정량 등급 유지, (3) 열거된 사유가 명확히 있을 때만 조정 — 정책 문서에서만 도출한다. 에이전트 출력을 보고 정하지 않았다.

골드는 정책이 '할 수 있다'(재량)고 규정한 조정을 '요건이 명확히 충족되면 조정한다'는 평가 규약으로 고정한 것이다. 정책의 의무 규정이 아니다(한계로 문서화 예정).
